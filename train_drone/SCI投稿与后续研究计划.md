## 2026-10-16 路线更新

近期代码与文献审计后，论文主线从“继续并列堆叠多个门控/注意力模块”调整为：

> **用一个受监督的共享小目标先验统一约束跨尺度融合，再通过尺度适配器保留各层差异；以切片因果对照和真实量化部署检验其有效边界。**

当前暂用 `STP-SCA` 作为工作名，不在新颖性检索和完整消融完成前固定正式模块名或使用“首次”。监督热图增强特征金字塔已有 SSPNet、SADENet 等先例，因此论文贡献必须落在“共享、跨层复用、尺度适配、YOLO Neck 集成和端侧验证”的组合机制及证据，而不是泛化地声称提出监督注意力。

近期优先级调整如下：

1. 先完成门控、o2o/o2m、Tile 数据分布和模型导出的四项诊断；
2. 用 30～50 epoch 筛选 STP-SCA，并通过“辅助监督但不门控”等对照识别真实增益来源；
3. 对入围方案进行同预算、3 seeds 和 `原图/Tile × 当前结构/STP-SCA` 的 2×2 正式实验；
4. 在 Raspberry Pi 5 上完成 FP32/FP16/INT8 一致性与延迟测试；
5. 切片—整图一致性只作为条件性扩展，P2 稀疏跳算只有具备真实运行时支持后再进入论文。

长尾 Copy-Paste、重复采样和 DMSSP 从近期主线降为备选。它们不是被判定无效，而是当前证据更支持优先解决“门控依据分散、Tile 增益来源不清和部署证据不足”三个问题。下方原 Phase B1/B2 计划保留为备选方案；与本节冲突时，以本节为准。

## 二、论文格式要求

### 2.1 Drones / Remote Sensing（MDPI 通用模板）

- 使用目标期刊投稿时提供的最新 Word 或 LaTeX 模板；先完成内容，再按期刊要求排版。
- 稿件逻辑：问题与研究空白 → 方法与复杂度 → 数据与公平对照 → 结果及误差分析 → 端侧测量 → 局限性与结论。最终栏目名称、摘要字数和声明项以投稿当日作者指南为准。
- 数据可用性声明只写实际公开的数据、代码和权重；尚未公开的内容不得写成“已开源”。

### 2.2 IEEE JSTARS

- 官方要求双栏、单倍行距投稿；摘要为 **150～250 词**。用投稿时的 IEEE 模板，并在提交前检查图像分辨率和图注。[官方作者指南](https://www.grss-ieee.org/publications/jstars-information-for-authors/)
- 该刊强调技术内容的新颖性、重要性和完整实验；若只把已有模块与数据增强叠加，投稿风险较高。

### 2.3 Scientific Reports（Nature 格式）

- 作为备选时，按当期作者指南确定栏目、篇幅、声明和图表格式。

### 2.4 其他档位期刊格式速记

- 其余候选期刊均以各自官网当前模板和作者指南为准；不能把 J-STARS 的页数、费用或版权规定直接套到 IEEE Access，也不能把一个 Springer 期刊的模板套到另一个期刊。

### 2.5 论文证据清单

1. **公平对照表**：同一数据划分、输入尺寸、训练预算、预训练权重、模型选择规则和评估脚本下，报告 mAP50、mAP50-95、各类 AP、参数量和 GFLOPs。历史探索结果另列，不混入正式对照。
2. **结构消融表**：每个模块的单独贡献、主要组合和删减对照；数据增强与网络结构分表呈现。
3. **误差分析**：PR 曲线、归一化混淆矩阵、分尺寸/遮挡/密集度结果，以及成功与失败案例。若要报告 APsmall，先明确小目标面积阈值及采用的评估实现。
4. **端侧结果表**：同一树莓派 5 配置下，分别报告预处理、模型推理、后处理和端到端延迟、P50/P95、峰值内存；模型文件大小单独报告。
5. **数据证据**：类别频次、按原图划分后的切片分布、小目标尺寸分布和数据泄漏检查记录。

## 四、后续详细研究计划

### Phase A：数据与基线审计（10-14 ～ 10-25）

**先固定协议**：按原始图像而非切片划分 train/val/test，核查跨划分重复图；记录数据版本及哈希、预训练权重、代码提交、输入尺寸、训练轮数、batch、学习率、增强、随机种子和验证脚本。模型选择统一为“按验证集 mAP50-95 选一个最佳 epoch，再报告该 epoch 的全部指标”，不得把不同 epoch 的最佳值拼成一行。

**再重训基线**：建议以现有正式方案确定统一训练预算（例如 150 或 200 epoch），对 YOLO26n 和进入最终比较的候选使用相同协议。先跑种子 0，再补种子 1、2；资源不足时优先补基线、最终精度模型和最终部署模型。旧基线训练仅 100 epoch，不能作为新实验增益的正式分母；另一模型旧结果更高也不能据此推断 YOLO26n 必然异常。

**通过条件**：拿到可复现的 mAP50、mAP50-95、按类 AP 和均值±标准差；完整保存配置与原始日志。参考命令见 §6.5。

### Phase B1：长尾类别策略（10-26 ～ 11-20）

在**相同模型结构**上做四组：原始训练集、仅 Copy-Paste、仅重复采样、两者组合。people、bicycle、tricycle、awning-tricycle 暂列重点类，是否属于尾部类以最终训练集的**实例数和含该类图片数**双重统计确认。实例库只来自训练集；验证集与测试集保持原样。

先以种子 0 筛选，再对可能写进主结论的方案补 1、2 两个种子。重点看四类的逐类 AP、总体 mAP50-95 和误检；“尾部类平均提升 5 个百分点且总体精度不下降”仅作为进入下一阶段的预设门槛。无效则停止，不把预计涨点写入摘要。

### Phase B2：尺度策略（11-01 ～ 11-20，可与 B1 并行准备）

把“训练切片”和“推理切片”拆开比较：原图训练/原图推理、切片训练/原图推理、原图训练/SAHI 推理、切片训练/SAHI 推理。若资源有限，先固定模型权重，只比较推理策略。切片训练时必须按原图先划分数据；评估应将预测映射回**原图坐标**，在同一原图标注上计算指标，不能把切片级 mAP 与整图级 mAP 直接相减。

每组记录切片大小、重叠率、合并方法、置信度与 IoU 阈值、每张图切片数及**总推理耗时**。Tile960 的旧结果提示尺度策略值得研究，但尚不能证明与长尾策略可相加；以实测决定是否保留。

### Phase C：组合、消融与部署（11-21 ～ 12-20）

**精度模型**从 P2/TGPFuse3/Tile960 路线选，**部署模型**从参数候选与低计算量候选中选。两者可以不同，不应预设把所有模块叠加就是最终模型。补齐 FGDDown、TGPFuse3、P5SPFPrune、TCA_P3 的替换/删减实验；数据策略另表消融。所有主结论至少用三个随机种子确认，并报告均值±标准差。

树莓派 5 测试固定内存容量、操作系统、散热、电源模式、推理后端及版本、精度、线程数、输入尺寸、batch=1、预热轮数、正式计时次数。记录预处理/推理/后处理、端到端 P50/P95、峰值内存和温度/功耗条件；至少 100 次正式计时，并在相同设备与脚本下比较基线。参数量下降不能直接推断延迟下降。

**阶段目标**：争取 mAP50 ≥ 0.48、mAP50-95 ≥ 0.30，同时验证部署模型是否位于精度—延迟 Pareto 前沿。这是管理目标，不是投稿必达值；若未达成，应基于实际结果重新界定贡献和期刊。

### Phase D：写作与投稿（12-21 ～ 2027-02-10）

论文由研究问题和证据驱动：先写研究问题、相关工作对比矩阵、实验协议和图表；每个贡献对应至少一组对照和一段误差分析，再写摘要与结论。最后与导师核对投稿期刊、作者顺序、经费和数据/代码声明。写作负责人需能追溯图表到原始日志和脚本，而非只负责语言润色。

## 五、候选改进及其证据边界

> 本节讨论可测试的训练与推理策略，不预设效果。自研模块是否构成论文贡献，同样须经相关工作检索、消融和独立验证；“自己写了代码”本身不足以证明新颖性。

### 5.1 尾部类 Copy-Paste

- **原理**：提高训练时尾部类实例的出现频率，以检验类别不平衡是否限制召回率。既有训练集统计提示类别不均衡，但正式论文应重算并保存统计脚本。
- **做法**：只从 train 构建实例库；记录每个实例来源及粘贴目标图，控制大小、遮挡、背景合理性和重叠。优先做少量人工可视化质检，再生成完整训练集；val/test 不变。矩形框裁剪只能作为试验性原型，不能把矩形背景一起粘贴后的结果解释成“无噪声实例粘贴”。
- **验收**：报告每类 AP、误检、总体 mAP50-95 和三种子方差；若只改善少数类却损害总体指标，需如实报告。

### 5.2 简化的稀有类别图片重复采样

- **原理**：让含稀有类别的训练图片更频繁出现，以改变梯度更新频率。下方固定重复次数的清单只借鉴 RFS 思路，不能称为 Detectron2/LVIS 原始 RFS 算法。
- **做法**：按**含该类的图片数 / 训练图片总数**估计类别频率，基于预设阈值生成重复采样清单；阈值和重复次数在验证集上选，禁止使用测试集调参。若训练框架对重复路径去重或缓存，须检查实际每 epoch 抽样分布。
- **风险**：重复同一图不会增加场景多样性，可能过拟合背景；单独与组合实验都需要报告。

### 5.3 基线重训对齐（地基）

- 见 Phase A。旧探索结果的训练轮数和选模条件不同，不能充当正式实验对照。

### 5.4 SAHI 切片推理 / 多尺度测试（推理期增强）

- **原理**：切片会使小目标在模型输入中的相对尺度增大，但也会增加每张原图的推理次数及合并开销。
- **做法**：在同一原图验证集上比较直接推理和切片推理，映射回原图坐标后计算 AP，并记录切片数、合并方法与端到端延迟。若树莓派 5 的实时性受损，应将其定位为高精度离线推理策略。

### 5.5（可选）蒸馏收尾

- 旧 TPKDStudent v1 在 width=0.20 下失败。投稿前不新增蒸馏主线；若后续重启，先归因失败并做独立对照。

## 六、实验执行接口与代码边界

### 6.1 Copy-Paste 实现前的检查

原稿中的 Copy-Paste 代码缩进丢失，而且直接粘贴矩形框会同时带入原图背景，不能作为已验证的可运行脚本。先保留下面的**实现规范**，在独立脚本中完成、抽样目检和小规模试跑后，再把脚本路径与提交号写回本计划：

1. 输入仅为冻结划分后的 `train/images` 和 `train/labels`；逐图记录来源，绝不读取 val/test。
2. 优先使用有分割掩码的实例；只有框标签时，将矩形裁剪明确标作“矩形粘贴基线”，统计伪边缘和背景伪影。
3. 候选粘贴位置与所有原有框及本轮新增框计算**真实 IoU**；另设过度遮挡阈值，不能用“交集 / 粘贴面积”冒充 IoU。
4. 图像和标签原子写入新目录；验证无空文件、越界框、同名覆盖、跨划分来源。保存随机种子和每张图实际粘贴数量。
5. 先人工检查至少 50 张生成图，再做完整训练；在论文中给出增强图例及失败案例。

### 6.2 稀有类别图片重复清单（最小实现示意）

以下代码只生成候选清单；运行前核对图片扩展名、路径和训练器是否保留同一路径的重复项。正式实验需要记录实际采样频率。

```python
from collections import Counter
from pathlib import Path

LBL_DIR = Path("datasets/VisDrone-YOLO/train/labels")
IMG_DIR = Path("datasets/VisDrone-YOLO/train/images")
OUT = Path("datasets/VisDrone-YOLO/train_repeated.txt")
TAIL_CLASSES = {1, 2, 6, 7}  # 按 data.yaml 核对
THRESH = 0.02  # 仅为待验证的超参数
REPEAT = 6  # 仅为待验证的超参数

items = []
images = sorted(p for p in IMG_DIR.iterdir() if p.suffix.lower() in {".jpg", ".jpeg", ".png"})
for image in images:
    label = LBL_DIR / f"{image.stem}.txt"
    classes = (
        {int(line.split()[0]) for line in label.read_text(encoding="utf-8").splitlines() if line.strip()}
        if label.exists()
        else set()
    )
    items.append((image.resolve(), classes))

if not items:
    raise RuntimeError("没有找到训练集标签")

freq = Counter()
for _, classes in items:
    freq.update(classes)
n = len(items)
print("类别图片频率:", {c: round(freq[c] / n, 4) for c in sorted(freq)})

lines = []
for image, classes in items:
    repeat = REPEAT if any(freq[c] / n < THRESH for c in classes & TAIL_CLASSES) else 1
    lines.extend([str(image)] * repeat)
OUT.parent.mkdir(parents=True, exist_ok=True)
OUT.write_text("\n".join(lines) + "\n", encoding="utf-8")
print(f"原 {n} 张 -> 重复后 {len(lines)} 条，写入 {OUT}")
print("先检查训练器是否保留重复路径，再在副本 data.yaml 中指向该清单。")
```

### 6.3 按类 AP 统计示意

```python
from ultralytics import YOLO
```

### 6.4 SAHI 单图可视化示意

### 8.2 候选贡献与验证门槛

| 候选           | 可以检验的机制主张                                   | 要求的对照                                                      |
